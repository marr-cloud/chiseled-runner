# Drop Node 20 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Default images ship only Node 24, to cut pull time when scaling onto new hosts.

**Architecture:** One build-arg default in the Dockerfile, a smoke test that pins it, a real-job check that `node20` actions still run, and before/after numbers.

**Tech Stack:** Dockerfile (BuildKit), GitHub Actions workflow `build.yml`, Docker Desktop locally.

**Spec:** `docs/superpowers/specs/2026-11-19-drop-node20-design.md`

## Global Constraints

- `ARG NODE_VERSIONS="24"` is the new default; `--build-arg NODE_VERSIONS="20 24"` must still produce an image with both.
- No `-node20` tags, no ICU changes.
- Local helper: `C:\Users\maurr\AppData\Local\Temp\claude\b8e8628cd661c1e7\5e813936-0cb5-48a6-b7f2-0b953d72e00f\scratchpad\ci-local.sh <release> <target>` replicates the CI smoke tests (set `MSYS_NO_PATHCONV=1` for `docker run` paths).

## Review Focus

- A workflow using `actions/checkout@v4` (declares `node20`) on the new image: expected to run on Node 24 and succeed. Pinned by Task 3's job.
- A workflow that sets `ACTIONS_ALLOW_USE_UNSECURE_NODE_VERSION=true`: expected to fail clearly; documented, not supported. Task 4 docs.
- `NODE_VERSIONS="20 24"` rebuild: both `externals/node20` and `node24` present. Task 2 Step 5.
- `hashFiles()` in a workflow (runner-internal Node): expected to work on Node 24. Pinned by Task 3's job.
- arm64 image: same pruning applies per arch; covered by the publish build on `main` (multi-arch), checked in Task 5.
